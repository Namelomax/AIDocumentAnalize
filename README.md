# Инспектор ИИ

Веб-сервис автоматической сверки строительной документации: проверяет
проектные и исполнительные документы на соответствие нормативным
требованиям и друг другу с использованием ИИ.

## Ссылки

- Репозиторий: https://github.com/Namelomax/AIDocumentAnalize
- Документация: [`docs/README.md`](docs/README.md)
- Инструкция по запуску и подключению ИИ: [`docs/ЗАПУСК_И_ИИ.md`](docs/ЗАПУСК_И_ИИ.md)
- Прототип — веб-интерфейс: [`services/web/`](services/web/)

## Требования к окружению

- Docker с Compose. NVIDIA Container Toolkit нужен только серверу модели
  (vLLM), если он запускается в Docker на GPU; сам стенд GPU не требует.
- На проверочном стенде используется GPU NVIDIA H100 80 ГБ.

## Как запустить

### На машине с интернетом

```bash
docker compose up
```

Сервисы `api`, `worker` и `web` соберутся из исходников, остальные образы
будут скачаны. Интерфейс открывается на `http://localhost:8080`.

> После правки исходников запускайте `docker compose up --build`: у `api`,
> `worker` и `web` задано поле `image:`, поэтому при обычном `up` компоуз
> возьмёт уже собранный образ и изменений в контейнере не окажется. Все переменные окружения по умолчанию заданы прямо в
`docker-compose.yml` (по значениям из `.env.example`), файл `.env` не
обязателен — создавайте его только если нужно переопределить какие-то
значения (например, пароли для боевого окружения).

### На проверочном стенде без интернета

Поставка включает архив образов `dist/inspector-images.tar`, собранный
заранее командой `scripts/build-offline-bundle.sh`.

```bash
docker load -i dist/inspector-images.tar
docker compose up
```

Так как у `api`, `worker` и `web` в `docker-compose.yml` указано поле
`image:`, `docker compose up` использует уже загруженные образы и не
пытается собирать их заново, поэтому сеть не нужна. Интерфейс открывается
на `http://localhost:8080`.

## Учётные записи

При первом старте, если таблица пользователей пуста, API создаёт четыре
демонстрационные учётные записи, чтобы на проверочном стенде было под кем
войти без участия команды:

| Логин | Роль | Пароль по умолчанию |
|---|---|---|
| `admin` | Администратор | `admin123` |
| `inspector` | Инспектор | `inspector123` |
| `supervisor` | Супервизор | `supervisor123` |
| `ml` | ML-инженер | `ml123` |

Пароли переопределяются переменными окружения `DEMO_ADMIN_PASSWORD`,
`DEMO_INSPECTOR_PASSWORD`, `DEMO_SUPERVISOR_PASSWORD`, `DEMO_ML_PASSWORD`.
Создание происходит только при пустой таблице `users`: как только появляется
хотя бы один пользователь, учётными записями управляют люди, и пересоздание
удалённой демонстрационной учётки при перезапуске отменило бы их решение.

Вход: `POST /api/v1/auth/login` с телом `{ "login": "...", "password": "..." }`
возвращает `{ token, user }`.

## Мониторинг

`docker compose up` поднимает вместе со стендом Prometheus
(`http://localhost:9090`) и Grafana (`http://localhost:3001`) с готовым
дашбордом «Инспектор ИИ — эксплуатация» и настроенными алертами. Подробности
— `deploy/monitoring/README.md`.

## Локальные модели (необязательно)

Без моделей система работает полностью, кроме двух функций, которые тогда
честно возвращают «модель недоступна» / `LOW_QUALITY`:

- гипотезы свободного поиска — `LLM_BASE_URL`, `LLM_MODEL`
  (проверено на `qwen/qwen3.8-27b`);
- распознавание сканов — `OCR_MODEL` (проверено на `glm-ocr`),
  адрес по умолчанию берётся из `LLM_BASE_URL`.

Любой OpenAI-совместимый сервер (vLLM на стенде, LM Studio при разработке),
например `LLM_BASE_URL=http://host.docker.internal:1234/v1`.

## Соответствие ТЗ

Сделано:

- загрузка пакетов с лимитами, антивирусом (ClamAV), реестром и выбором
  актуальной редакции; дозагрузка до финализации без сброса решений;
- разбор PDF с координатами (учёт CropBox/Rotate), кеш разбора в Redis;
- проверка 99 из 132 параметров Матрицы: сверка экспликаций помещений
  ПД↔РД (M-003, на эталоне найдено пилотное нарушение 1.109) и общий
  механизм для 95 текстовых параметров и 4 параметров наличия документа;
- статусы CANDIDATE / NEGATIVE_VERIFIED / MISSING_EVIDENCE / NOT_COMPARABLE /
  CLARIFICATION_REQUIRED; составные кандидаты с разбиением;
- гипотезы свободного поиска (SUSPICION) на локальной модели;
- верификация инспектором с кодами причин, финализация и её отмена, версии
  протокола, экспорт PDF/DOCX/XML, передача в ИАИС «РиН» с повторами
  (на стенде — локальная заглушка `rin-mock`);
- GOLD-метки из решений, версии набора данных, метрики precision / recall /
  FPR по разделу 14.3 и еженедельный отчёт;
- роли и JWT, журнал аудита, уведомления, повторы при сбоях, Prometheus и
  Grafana с алертами, ежедневная проверка целостности хранилища.

Не сделано или сделано частично:

- 33 параметра по чертежам (`drawing_entity`, `drawing_measure`) —
  отвечают «требуется анализ чертежа»;
- OCR подключён, но точность ниже порога ТЗ (1 − CER 0,225 при 0,95,
  см. `docs/quality/ocr-eval.json`); доработка — ветка `wip/ocr-v2`;
- поиск значений текстовых параметров проверен на синтетическом пакете,
  на настоящих таблицах ТЭП ещё не проверялся;
- параметры наличия документа (M-098…M-101) описывают регистрацию во
  внешних системах и без их выгрузок дают MISSING_EVIDENCE;
- разбор содержимого DOCX/XML-документов, логические и нормативные
  правила гипотез, ELK, валидация по OpenAPI, нагрузочные испытания.
